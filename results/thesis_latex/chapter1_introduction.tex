\chapter{Introduction}
\label{chap:introduction}

Small connected devices now sit inside factories, hospitals, power substations and ordinary homes. Most of them were designed to be cheap and power-efficient, not secure. They run stripped-down firmware, are rarely patched, and often stay in the field for years with default settings. Together they give attackers a large and poorly defended surface, and a single compromised sensor or camera can become an entry point into a much more valuable network.

Because the devices themselves can seldom protect themselves, security is usually pushed to the network. A Network Intrusion Detection System (NIDS) watches traffic flowing through a gateway and raises an alarm when the traffic looks malicious. Older NIDS matched packets against hand-written signatures of known attacks. Over the last decade this has largely given way to machine learning models that learn the statistical shape of each attack from labelled flow records. On public benchmarks such models routinely report accuracies above 95\%, and tree ensembles such as Random Forest~\cite{breiman2001random} are especially popular because they are accurate, fast and easy to interpret.

Those benchmark figures hide an awkward fact. A supervised classifier only knows the classes it was trained on. In a real deployment, attackers do not stay within that list: new malware families appear, old techniques are combined in new ways, and devices are exposed to traffic that nobody labelled. When such traffic arrives, the model does not say ``I do not know''. It confidently assigns the flow to the nearest familiar class, and the attack passes unnoticed. Once the new attack has been identified, the model has to be updated, and on an edge gateway with limited memory and processing power that update is itself a hard problem.

This thesis is motivated by that gap between benchmark performance and deployed behaviour. It asks how an IoT intrusion detector can keep learning new attacks after deployment without forgetting the old ones, and without needing more memory or computation than an edge device can offer.

\section{Problem Definition}
\label{sec:problem_definition}

The problem studied here has two linked parts. The first is \emph{detection}: a deployed model must be able to notice that some traffic does not belong to any class it knows. The second is \emph{adaptation}: once that traffic is confirmed as a new attack, the model must learn it quickly while still recognising everything it learned before. Each part is easy to solve on its own. Solving both together on constrained hardware is what makes the problem difficult.

\subsection{Why Static Detectors Miss Unseen Attacks}
\label{subsec:closed_world}

A standard classifier is trained under what is called the closed-world assumption: every sample it will ever see belongs to one of the $K$ classes present in the training data. Its output layer, or in the case of a Random Forest its set of leaf labels, simply has no option for anything else. An unseen attack is therefore not rejected; it is mislabelled.

We measured how severe this is. Using a leave-one-attack-out protocol on the TON\_IoT dataset~\cite{alshammari2020toniot}, we removed one attack class from training at a time and tested the resulting model on it. The baseline Random Forest reached 97.2\% overall accuracy, yet its F1 score on each held-out attack (MITM, ransomware, XSS and backdoor) was exactly zero. Every unseen flow was assigned to some known class.

As shown in Figure~\ref{fig:closed_world_failure}, while the model maintains a high known-class mean F1 of 0.989, unobserved MITM flows are silently misclassified into existing classes---predominantly DoS (40.9\%) and Normal traffic (28.0\%). This confirms that high static benchmark accuracy provides false assurance in dynamic network environments.

Unsupervised anomaly detectors such as Isolation Forest~\cite{liu2008isolation} take a different route. They learn what ordinary traffic looks like and flag whatever deviates from it, so in principle they can react to attacks they have never seen. In practice their signal is weak and noisy. In our experiments Isolation Forest flagged only 18.9\% of unseen MITM flows. That is useful as an early warning, but it cannot replace a classifier that tells the operator \emph{which} attack is under way.

\subsection{The Cost of Updating a Deployed Model}
\label{subsec:update_cost}

Suppose the new attack has been flagged and a few hundred labelled examples are available. There are three obvious ways to update the model, and each has a serious drawback on an edge device.

\subsubsection*{Retraining on new data only}
The cheapest option is to train only on the new attack samples. This learns the new class almost perfectly but destroys what the model knew before. The effect is known as \emph{catastrophic forgetting}~\cite{kirkpatrick2017overcoming, parisi2019continual}: the decision boundaries that separated the old classes are overwritten by boundaries fitted to the new data. In our experiments, a model updated this way lost essentially all of its ability to recognise the original attack classes.

\subsubsection*{Full retraining}
The opposite option is to keep the complete historical dataset and retrain from scratch on old and new data together. This avoids forgetting, but it requires storing well over a hundred thousand flow records on the device and repeating the full training cost for every update. Less obviously, it also performs poorly when the new attack is rare. With 207 MITM samples mixed into 127{,}787 historical flows, the retrained model learned MITM with an F1 of only 0.648, because the new class was swamped by the old ones.

\subsubsection*{Fixed-size replay}
A middle path, borrowed from the continual learning literature~\cite{lopezpaz2017gem, de2021continual}, is to keep a small buffer of representative old samples and replay them alongside the new data. A buffer of 100 samples per class worked very well for the small MITM attack (F1 of 0.977 with 99.3\% less storage). The trouble begins when the new attack is large. Attacks such as XSS and backdoor arrive with thousands of samples, which outnumber a fixed buffer many times over. The model then tilts towards the new class, and the worst-affected old class lost up to 0.397 in F1. A buffer size that suits one attack is therefore the wrong size for another.

\subsection{Problem Statement}
\label{subsec:problem_statement}

Let $\mathcal{D}_{\text{train}}$ be the historical training data over $K$ known classes, and let $\mathcal{D}_{\text{new}}$ be a batch of $M$ labelled samples from a newly identified attack. The problem addressed in this thesis is to update a deployed classifier using $\mathcal{D}_{\text{new}}$ and a small subset of $\mathcal{D}_{\text{train}}$ so that:
\begin{enumerate}
    \item the new attack is detected with high F1;
    \item performance on the $K$ known classes drops as little as possible, measured by average and maximum forgetting;
    \item the number of stored historical samples stays within a fixed memory budget; and
    \item the update completes in a time that is practical on an edge gateway.
\end{enumerate}
These requirements must hold whether the new attack is small (a few hundred samples) or large (several thousand).

\section{Objectives}
\label{sec:objectives}

The work in this thesis is organised around four objectives:
\begin{enumerate}
    \item To quantify how badly a closed-world IoT NIDS fails on attacks it was not trained on, and how much an unsupervised anomaly detector can recover.
    \item To compare full retraining, retraining on new data only and fixed-size replay in terms of new-attack detection, forgetting, memory use and update time.
    \item To study how replay buffer size trades memory against retention of old knowledge.
    \item To design and evaluate a replay allocation rule that adapts to the size of the incoming attack, so that forgetting stays bounded for both small and large attacks.
\end{enumerate}

\section{Contributions}
\label{sec:contributions}

To achieve these objectives, this thesis introduces a closed-loop dual-stage framework for IoT edge intrusion detection, illustrated in Figure~\ref{fig:framework_overview}.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=\textwidth]{results/figures/chapter1/fig1_4_framework_overview.pdf}
    \caption{Overview of the proposed two-stage continual intrusion detection framework: Stage~1 performs real-time edge classification alongside unsupervised anomaly screening for novel traffic; Stage~2 performs volume-aware dynamic replay buffer allocation and efficient on-device model adaptation upon analyst verification.}
    \label{fig:framework_overview}
\end{figure}

The main contributions of this thesis are as follows:
\begin{enumerate}
    \item \textbf{A measured account of the unseen-attack failure.} Under a leave-one-attack-out protocol on TON\_IoT, a 97.2\%-accurate Random Forest scores zero F1 on all four held-out attacks, while Isolation Forest recovers only part of the novel traffic.
    \item \textbf{Evidence that naïve full retraining is not an upper bound for rare attacks.} Replaying 100 samples per class raises MITM F1 from 0.648 to 0.977 while storing 99.3\% fewer samples and updating about 11$\times$ faster.
    \item \textbf{A volume-aware Dynamic Replay rule.} The per-class replay quota is scaled with the size of the incoming attack, within fixed lower and upper memory bounds. Compared with a fixed buffer, it reduces maximum forgetting by 20--36\% and average forgetting by up to 40\% on the three high-volume attacks, keeps new-attack F1 above 0.997, retains 96.8--97.6\% memory savings and completes each update in under 0.1~s.
    \item \textbf{A buffer-sensitivity analysis.} Forgetting falls steadily as the buffer grows, and even 25 samples per class (a 99.8\% reduction) learn MITM with an F1 of 0.980. This gives practitioners a clear way to choose a buffer size for a given memory budget.
\end{enumerate}

\section{Scope and Assumptions}
\label{sec:scope}

A few boundaries of this work should be stated at the outset. All experiments use flow-level features from a single public dataset, TON\_IoT, so the results show what is achievable on that data rather than across every IoT environment. The adaptation step assumes that labelled samples of the new attack are available once it has been flagged, for example from a security analyst; fully label-free adaptation is outside the scope. The classifier is a Random Forest throughout, chosen for its accuracy and low inference cost. Update times were measured on a general-purpose CPU and are reported as relative comparisons between strategies, not as benchmarks on a specific edge device.
